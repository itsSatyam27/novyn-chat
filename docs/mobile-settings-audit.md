# Android settings audit

Reviewed the Flutter settings menu, subpages, preference storage, runtime consumers and the shared backend. This is a source review; it does not claim that every flow was exercised on a physical device.

The main menu now places Preferences before Account. Its compact cards and floating status selector are consistent, but several subpages still use larger, independently implemented cards. More significant than the visual differences: a number of controls save a local preference or display success without performing the promised operation.

## Findings to address first

| Priority | Setting | Current behavior and evidence |
| --- | --- | --- |
| High | Two-Factor Authentication | The setup advances after delays and sets a local boolean. It does not send or verify an OTP or enforce a second factor at sign-in. See `_nextStep` and `_finalize` in [security_privacy_screen.dart](../apps/mobile/flutter/lib/screens/profile/settings/security_privacy_screen.dart). |
| High | Delete Account | The confirmation handler contains `Logic to delete account would go here` and displays a success-like snackbar. It does not delete the account. Same security/privacy screen. |
| Resolved | Change Password | Mobile now uses the existing `change_password` socket protocol and reports success only after server confirmation. The server requires at least 12 characters for a new password. Web directs changes to mobile. [auth_service.dart](../apps/mobile/flutter/lib/services/auth_service.dart), [server.js](../apps/api/server.js). |
| High | Last Seen / Profile Photo privacy | Mobile posts to `/api/profile/privacy`, which has no matching backend route. Preferences alone do not enforce visibility for other users. Invisible presence has a separate backend implementation. Same API service and server. |
| High | App Lock | Startup does set the initial lock when app lock is enabled and a PIN exists. Remaining gaps: PINs are stored in plain SharedPreferences, and the resume handler permits a five-second grace period even when the timeout says Immediately. [settings_service.dart](../apps/mobile/flutter/lib/services/settings_service.dart), [app_lock_wrapper.dart](../apps/mobile/flutter/lib/widgets/app_lock_wrapper.dart). |
| High | Notifications master switch / previews / group alerts | Preferences are saved, but runtime notification handling does not consume these switches. Busy mode has its own mute handling. | Medium | Profile editing | Mobile posts to `/api/profile/update`, while the backend uses `update_profile`. A local profile update can therefore disagree with server data. API service and [edit_profile_screen.dart](../apps/mobile/flutter/lib/screens/profile/edit_profile_screen.dart). |
| Medium | Notification tone / ringtone / vibration pattern | Preview and preference saving exist, but the socket and call screen use fixed audio assets. Selecting a tone does not change the actual received-message or incoming-call sound. [sound_vibration_screen.dart](../apps/mobile/flutter/lib/screens/profile/settings/sound_vibration_screen.dart), [socket_service.dart](../apps/mobile/flutter/lib/services/socket_service.dart), [call_screen.dart](../apps/mobile/flutter/lib/screens/calls/call_screen.dart). |
| Medium | Blocked Users | The settings list and unblock action use local blocked IDs; they are not synchronized with the server's authoritative block list. Security/privacy screen and settings service. |
| Medium | Stealth icon | Native code references launcher aliases, but the Android manifest explicitly removes aliases for debug. The switch can save a preference without changing the launcher icon. [MainActivity.kt](../apps/mobile/flutter/android/app/src/main/kotlin/com/example/novyn/MainActivity.kt), [AndroidManifest.xml](../apps/mobile/flutter/android/app/src/main/AndroidManifest.xml). |

## Other menu and subpage gaps

- QR generation works; the QR share action is still a placeholder. The dialog should scroll on shorter screens.
- Help & Support displays static guidance; Contact Support opens a coming-soon message.
- Data & Storage and Accessibility screens are now linked from the Android main settings menu.
- Storage usage numbers are hardcoded. Clear Cache displays success without clearing data; media download and quality choices have no runtime consumer. [data_storage_screen.dart](../apps/mobile/flutter/lib/screens/profile/settings/data_storage_screen.dart).
- Language preference reaches `MaterialApp.locale`, but many subpage labels remain hardcoded English. Region/date/time/number choices are not consistently applied; some dialog choices only close the dialog. [language_region_screen.dart](../apps/mobile/flutter/lib/screens/profile/settings/language_region_screen.dart).
- Accessibility font size changes the preview rather than the application text scale. High Contrast and Reduce Motion are coming-soon options. [accessibility_screen.dart](../apps/mobile/flutter/lib/screens/profile/settings/accessibility_screen.dart).
- Most preferences are global to the installed app, not scoped per account or synchronized between Android and web.
- Subpage labels such as “Auditory Node Styles” and “Purge Node” obscure ordinary actions. Use familiar labels such as “Notification sound” and “Delete account.”

## Web comparison before the mobile-managed policy, checked on 7 October 2026

- Web has wallpaper and font-family/message-size controls, an always-visible-dock preference, backend-saved retention selection, feedback forms and JSON export/import screens that Android's main settings menu lacks. Android has System theme, PIN/biometric lock, stealth/privacy selectors and more haptic controls that web lacks.
- Before the mobile-managed settings change, Web Change Password only validated fields and displayed success; Android used a mismatched REST route. Web now directs password changes to Android, and Android uses the existing `change_password` socket protocol, waits for server confirmation and requires the server's 12-character minimum.
- Web message-preview preferences still only write localStorage without a runtime consumer. The web read-receipt switch has been replaced with mobile-app guidance; Android read-receipt enforcement still needs repair.
- Web Active Sessions, Linked Devices and Account Actions now show explicit coming-soon guidance. The static session card and misleading Sign Out All action have been removed; normal browser logout remains on the main Settings page.
- Web JSON export contains profile/conversation summaries, not full chat history. Its import verifies a file and displays a restored message without restoring application state. This is separate from the working protected message-key transfer added for Android encryption compatibility.
- General preference synchronization is missing: web uses localStorage and Android uses SharedPreferences. Existing shared backend fields cover profile, presence and retention rather than a unified settings record.

## Message issue handled before settings changes

Android previously discarded encrypted message metadata and had no decryption implementation. The new message-key import stores conversation keys in secure storage and retains ciphertext/IV in the local database. The web export protects these keys with a transfer password and preserves the browser's non-extractable private identity. Import is required once from the original browser; repeat for new contacts or changed conversation keys. No backend deployment is required for this transfer format because the existing message envelope and public-key lookup protocol are reused.

Suggested settings repair order: remove false-success security flows; fix API/socket routing and server privacy enforcement; connect notification and audio preferences; enforce app lock at startup; then unify subpage density, wording, localization and accessibility.

## Mobile-managed settings policy

Android retains all its settings menus, including Data & Storage and Accessibility. Web exposes controls needed while using a browser: light/dark/system theme, dock visibility, wallpaper, font family/size, reduced motion, high contrast, language/region, message sounds, call sounds, desktop notifications, previews, profile details, presence, blocked contacts, retention, QR download, temporary-file cleanup, chat-data export and feedback. Web sections are explicitly enabled through `settingsAvailability.ts`; other sections retain mobile guidance.

Browser preferences are saved locally and consumed by the running web app. Desktop notification permission is requested from the settings button, rather than automatically on sign-in. The notifications and preview switches control the actual foreground notification flow. The React app does not register the legacy PWA service worker; these controls do not promise closed-browser push behavior. Incoming call sound/haptics respect call-sound and Busy preferences. Accessibility controls affect CSS animations and Framer Motion.

Profile/presence/retention changes wait for the backend's `profile_updated` confirmation. The previously missing `set_block` server handler validates requests, persists the block list, blocks messaging/calls, hides presence/last-seen between blocked users and ends their active call. Web restores its block/mute lists from session safety state. These account changes use the shared backend; browser appearance/audio preferences are not synchronized to Android.

Password, username/email changes, app lock, last-seen/profile-photo visibility, stealth and read receipts still point to the mobile app. Unfinished 2FA, session/device management and deletion retain coming-soon notices. The Android privacy and preference-consumer gaps above still need separate work.

Web browser-session sign-out is available once, through the settings sidebar's fixed Log Out action and confirmation dialog. The sidebar uses small icons and a compact profile summary. Profile opens a dashboard with a live profile preview, confirmed presence controls, a downloadable QR code, avatar selection and name/bio editing. Save and Discard remain visible while scrolling; changing presence preserves unfinished profile edits. Profile confirmations appear as a top popup for 3.5 seconds. Presence and QR are available in the profile cards rather than duplicated in sidebar navigation. Username and email actions open mobile-app guidance. Appearance opens a dashboard with light/dark/system previews, the dock toggle, a rounded font menu with keyboard and touch support, a smooth text-size slider and a live chat preview. Intermediate sizes are restored after reload, and dragging saves the preference on release. Theme and wallpaper selections use a single rounded border. Wallpapers have larger previews, visible names and description tooltips, with original mountain, ocean, pastel, desert and starry-sky backdrops. The selected backdrop applies to chats and survives reload. Language & Region and Accessibility remain in their own sidebar sections without duplicate Appearance cards. Both dashboards use the primary sidebar, with cards stacking on mobile. Other settings navigation groups available web controls, mobile-managed controls and upcoming features. Desktop uses a vertical navigation list; smaller screens use a grouped selector. Protected message-key export is available through Sync Message Keys in settings and Transfer message keys on the Messages screen, because original encryption keys must be exported from the browser that owns them. Temporary-file cleanup removes Novyn shell caches and temporary cache entries, preserving encryption identity, saved notes, preferences and sessions. Chat export includes profile, chat-list summaries and currently loaded messages; it does not claim a full-history backup or offer a fake restore action. Feedback waits for the server's HTTP success response.

Web Sounds & Notifications opens a single responsive dashboard with message and call toggles, Drift/Pulse/Glass/Echo chimes, message and call volume sliders, ringtone/ringback previews, and a live Busy-status card. Incoming audio uses the saved chime and volumes; zero message volume also silences browser notification audio. Previews stop when muted, replaced, or when leaving the page, including mobile Back navigation. Call previews use the same animated waveform, play/stop button and volume control as message previews, with Ringtone and Ringback selectors. Vibration controls and browser vibration calls are removed; native phone haptics remain available. There is no duplicate Browser Notifications shortcut. Browser sound preferences remain local.

Notifications are merged into the sound dashboard, with one sidebar entry and no secondary notification menu. The notification section includes desktop alerts, message-preview privacy, current browser permission and an illustrative preview. A blocked or unsupported browser shows the notification switch off and disabled; permission is requested only from an explicit enable action. Permission is refreshed when returning to the page. Existing alert preferences and actual incoming-notification behavior are preserved.
